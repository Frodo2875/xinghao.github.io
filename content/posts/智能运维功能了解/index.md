## 一、智能诊断要做什么

**总体**：从原来的“查看和解决问题”到“主动发现、分析和辅助决策”的智能诊断。

1. **性能监控** → 识别异常和变化趋势。
2. **告警 & 人工处理** → 关联异常数据，辅助判读分析。

1–2 属于智能诊断的功能。

3. **从异常分析和人工检查优化** → 识别原因 & 给出建议。
4. **人工巡检和报告** → 主动巡检和报告。

## 二、运维知识

### 常见异常和原因

| 故障类型 | 常见表现 | 诊断需要的数据 | 可能原因 | 常见处理思路 |
| --- | --- | --- | --- | --- |
| CPU 使用率高 | CPU 持续升高，响应变慢 | CPU、QPS、活跃会话、Top SQL、慢日志 | 高并发、低效 SQL、执行计划变化 | SQL 优化、控制并发、评估资源 |
| 慢 SQL | SQL 执行耗时增加 | 慢日志、执行计划、表结构、索引、扫描行数 | 索引不合理、扫描数据过多、锁等待 | 调整 SQL、评估索引、排查等待 |
| 锁等待 | 查询阻塞、事务执行慢 | 锁等待关系、事务信息、会话、SQL | 长事务、并发更新冲突 | 识别阻塞源、优化事务 |
| 连接异常 | 连接数过高、连接失败 | 连接数、活跃会话、连接错误、应用日志 | 连接泄漏、连接池配置、流量激增 | 排查连接来源、调整连接策略 |
| 内存异常 | 内存持续升高、响应波动 | 内存指标、缓存、会话、运行状态 | 工作负载变化、参数配置、资源不足 | 分析内存使用、评估参数 |
| 磁盘 I/O 异常 | 查询延迟增加、读写变慢 | IOPS、吞吐、I/O 延迟、SQL 访问行为 | 大量扫描、写入高峰、存储瓶颈 | 优化访问行为、评估存储 |
| 存储空间不足 | 使用率持续增加 | 容量趋势、表空间、增长记录 | 数据持续增长、历史数据未清理 | 容量规划、归档、扩容 |

> 企业那边更懂。

4. 运维知识和经验。

## 四、智能诊断与传统诊断的不同

| 环节 | 传统诊断 | 智能诊断 |
| --- | --- | --- |
| 1. 发现异常 | 达到条件出现异常 | 根据经验和当前状态识别异常 |
| 2. 定位异常 | 人工看大盘 | 自动标记异常时间段 |
| 3. 关联数据 | 人工看（如慢 SQL、日志等） | 关联异常时段中的相关运行数据 |
| 4. 判断原因 | 运维人员根据经验判断 | 根据经验给出可能原因和依据 |
| 5. 处理问题 | 人工查找并解决 | 根据问题特征给出建议 |

至于 Agent 交互，用自然语言组织进一步排查（是否考虑，需要做的话什么程度），同时判断原因不等于确认原因，还需要验证。

Agent 要做的事儿就是对于用户的自然语言，理解诊断目标，查阅（收集）相关信息，分析可能原因，验证，生成诊断结果，继续追问。
